Here's the full breakdown of each layer in the architecture:
Layer 1 — Orchestrator agent is the brain. It parses user intent (topic, tone, language, avatar, duration), routes tasks to the right skill, manages state between steps, and handles retry/error recovery.
Layer 2 — Skill modules split the work into two tracks: Script & Content (LLM-powered script generation with tone, language and length controls) and Visual Assets (everything visual that wraps the avatar).
Layer 3 — Invoked skills are the concrete capabilities the agent pulls in:

SKILL: docx — generates speaker notes and full scripts as downloadable Word docs
SKILL: pdf — produces storyboard briefs and shot lists
SKILL: pptx — builds slide decks with branded overlays the avatar presents over
SKILL: frontend-design — renders the preview UI and control panel (voice picker, style sliders, etc.)
SKILL: file-reading + SKILL: pdf-reading + SKILL: xlsx — invoked on-demand when the user uploads source material (a brief PDF, a data CSV for data-driven scripts, an existing deck)

Layer 4 — Avatar generation engine talks to external APIs (HeyGen, D-ID, Synthesia, or a self-hosted model) and handles TTS, voice cloning, lip-sync, multi-language, and custom avatar uploads.
Layer 5 — Enhancement pipeline runs post-generation passes: background removal/replacement, auto-captioning with style presets, logo/watermark branding, background music mixing, and upscaling/denoising for quality.
Layer 6 — Review & iterate loop renders a preview, lets the user compare variants (A/B), give feedback on specific segments, and re-run only the changed segment — not the whole video.
Layer 7 — Output delivery exports in the target format: MP4, WebM, animated GIF thumbnail, a PPTX with the video embedded, or a shareable streaming link.
The dashed feedback arrow on the left represents the iteration path — any output can route back to the orchestrator with notes, regenerating only the affected segment.
